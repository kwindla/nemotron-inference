Reconciliation notes
--------------------

- `atom_threads = 32` matches the expected SM120 `m16n8` warp-sized atom. The probe used `cute::size(typename TiledMma::AtomThrID{})`, which is equivalent to the requested `size<0>(...)` for this 1-D thread layout and is the constexpr form accepted by this CUTE snapshot.
- `stages = 4` and `thread_count = 256` match the TRT-LLM P1 compile-probe surface (`DispatchPolicy::Stages`, `ThreadCount`) for the `128x128x128`-element CTA / `1x1x1` cluster configuration.
- `SmemLayoutA/B` total cosize `65536` is reconcilable with four pipeline stages of a `128 x 128` FP4 operand tile: `128 * 128 * 4 = 65536` unpacked shared-memory elements.
- `SmemLayoutSFA/SFB` total cosize `4096` is reconcilable with four stages of block-scale storage at `K / 16 = 8` scale columns per `128`-wide M/N tile: `128 * 8 * 4 = 4096`.
- `tCrSFA = (64, 2, 2)` and `tCrSFB = (64, 8, 2)` are internally consistent with the `CTA_K = 128`-element (`2 x k64`) P1 mainloop: both scale fragments report `size<2> = 2` K-substeps.
- `tCrC_profile = (4, 2, 8)` matches the documented TRT-LLM accumulator profile family from `trtllm_architecture.md` §5.3: the accumulator N-mode remains `8`, which is the load-bearing contract for the per-thread MMA accumulation surface.
- `tCrA_k0` and `tCrB_k0` were measured on the stage-resolved A/B slices (`sA(_, _, Int<0>{})`, `sB(_, _, Int<0>{})`) because that is the partition surface that compiles against the flashinfer CUTLASS snapshot vendored in this repo. This is consistent with the existing backend kernels, which also resolve the stage axis before partitioning A/B fragments.
- `tCrC_profile` was measured via the free-function form `cute::partition_fragment_C(tiled_mma, make_shape(Int<128>{}, Int<128>{}))`, which is the equivalent compile-time surface for TRT-LLM's printed `accum_profile` on this CUTLASS snapshot.
